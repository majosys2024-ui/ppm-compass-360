Recommended: Test New Releases on a Sandbox Site First Deployment Best Practice

Every update automatically migrates your existing SharePoint list data forward so it works seamlessly with the new release. However, because new versions frequently introduce structural additions to lists (such as new governance columns, calculated fields, or views), rollbacks to older package versions are not supported once upgraded.

We strongly suggest creating a dedicated sandbox or staging SharePoint site in your tenant to validate new releases before applying them to your production PMO sites.

Enterprise Maintenance & Update Guarantees

Designed specifically to comply with enterprise IT governance and zero-risk change controls.

How do updates reach my tenant?

PPM Compass 360 is packaged as a standard Microsoft SharePoint Framework (SPFx) package (.sppkg). You upload the updated package to your tenant App Catalog and click Deploy. Zero server access or PowerShell scripting required.

How does data migration work during updates?

All your data lives securely in your own SharePoint Online lists inside your tenant. Each release automatically migrates and adapts existing list items so they work with the new version. Your historical status reports, milestones, risks, and audit logs are fully preserved.

Can I roll back to an older version?

No. Backward rollbacks are not supported. When a new release introduces structural changes to SharePoint lists (such as new columns, views, or calculations), the list schema moves forward. For this reason, we strongly suggest testing each new package on a staging/sandbox site before rolling it into production.

How do we get notified of new updates?

Customers receive proactive release notifications with download links and changelogs. You control the deployment timing in your tenant App Catalog and can validate on a sandbox site at your own pace.
