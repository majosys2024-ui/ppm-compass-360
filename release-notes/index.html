Recommended: Test New Releases on a Sandbox Site First Deployment Best Practice

After each update, a Site Owner runs Setup once (the app shows a reminder). Setup carries your existing SharePoint list data forward to the new release. However, because new versions frequently introduce structural additions to lists (such as new governance columns, calculated fields, or views), rollbacks to older package versions are not supported once upgraded.

We strongly suggest creating a dedicated sandbox or staging SharePoint site in your tenant to validate new releases before applying them to your production PMO sites.

v1.8.3 | Attention Marks, Multi-Year Finance & Excel Import List

Latest Release
8 November 2026 — Production Build (SPFx 1.8.3.3)

Package Version 1.8.3.3

No new lists or columns and no Setup run needed when updating from 1.8.2. One new optional setting (Currency). Direct update from any earlier version (earlier versions run Setup once as before; see upgrade instructions).

Data Kept: Setup only adds what is missing. All projects, reports, milestones, configurations and permissions stay as they are.

Security & Architecture

  • 🔒 Unchanged Security Footprint: No change to access: no Microsoft Graph or API permissions, no calls outside the SharePoint site. The new links in exports point strictly to this app's own page on the site.

What's New in Visual Governance & Portfolio Management

  • ⚑
    Items that need attention are marked, with the exact same rules across every screen:
    • • Milestones: ‼ Overdue, ! Past due, ◷ Due soon (before the next status report), ↘ Delayed, ⚠ At risk. A milestone still Not Started when it is due soon or late says so clearly, for example "○ Not started · due soon".
    • • Risks and issues: ‼ Overdue or ◷ Due soon by their target resolution date, ✎ Owner missing or ✎ Action missing (High and Critical), ? No target date (open issues). Resolved, Closed and Accepted items are never marked.
    • • Projects still Not Started after their planned start date: ○ Start date passed.
    • • Where you see them: the status report review step (summary line, marked items first, target dates for risks), the project Milestones and Risks & Issues tabs ("⚑ 3" badge on the tab, Needs attention filter, and Target column for risks), All Milestones, All Risks & Issues (Needs attention filter), My Projects, My Portfolio, All Projects, and executive exports.
  • 📌 Next Milestone on Project Cards: The card view in All Projects displays the next upcoming milestone (for example "Next: User acceptance testing · Q4 2026") alongside its attention status mark.
  • 📅 Figures by Year: Financial Burn (My Portfolio) and the Strategy pages feature an interactive Year picker. A year's actual spend and latest estimate (LE) derive from each project's last import of that year, so closed projects count in the years they actively ran ("incl. 1 closed"); total project budget continues to cover active projects only, and archived projects never count. Year totals indicate the relevant import months ("imports 05–09.2026"), and any actual exceeding its LE is marked with ⚠.
  • 🏁 Closing Date as a Milestone: Setting a project state to Closed automatically creates a completed "Project closed" milestone stamped with that day's date; reopening a closed project marks that milestone as Cancelled. When choosing Closed in Edit Project, the dialog shows how many milestones remain open.
  • 📁 My Portfolio: Active Projects by Default: Closed projects are filtered out by default to maintain portfolio focus, unless Show closed projects is toggled on.
  • 📊 Finance Import List (Excel): Site Owners and the PPM team can export Reports ▾ → Finance import list (Excel): lists every active project with its ERP number and current PPM figures, the exact template to fill in, and complete completion instructions.
  • 💱 Configurable Currency: Site Owners can set Settings → Currency (for example CHF, €, $, CAD, £). This custom currency symbol dynamically labels amounts in the Financials tab, budget headers on Strategy and Financial Burn, and executive exports (e.g. "Budget 2.1M CHF", "CHF used").
  • 📄
    Export Enhancements:
    • • Portfolio Pack One-Pager: Keeps project status, key figures, latest achievements, and forward plans on a single page. Text is truncated only when selecting Shorten; with Continue on a new page (default), long updates move seamlessly to the next page.
    • • Detailed with Timeline: Appends each project's timeline to the pack. Timelines render at most 20 milestones (first and last always included, then those nearest today) with collision-free labels, clearly noting how many milestones were omitted.
    • • Late Status Report Indicators: Unsubmitted reports are highlighted with a red (overdue) or amber (due) "!" adjacent to the project number, detailed as "3 overdue · 2 due" in the Reporting compliance tile, and noted as "Status report overdue / due" on project pages.
    • • Optional Footer Navigation Link: Footer → Link to the project provides deep links on exported pages to open the exact matching project tab directly in SharePoint (e.g. "Open P-28 · Milestones »").

Accessibility, Responsive Layout & Visual Refinements

  • 👁️ Readable Without Colour (WCAG): Every attention marker features its own distinct geometric symbol and border style (solid, dashed, outlined, dotted), ensuring full legibility for users with red-green colour vision deficiency. Due soon is styled in accessible blue.
  • 🗓️ Consistent Period End Counting: Month and quarter dates consistently count from the end of their period across all screens, marks, tiles, timeline colours, Strategy, and exports: "Q4 2026" is treated as due soon in December and past due in January.
  • 📈 Milestone Trend Chart Polish: When an open milestone's date has passed, its trend line terminates in a red ! with a dotted line extending to the current month, accompanied by the header notice "date passed …, still open". Baseline curves for completed milestones cleanly terminate at their completion date.
  • 🖥️ Viewport-Fitting Tables ("Fits the Screen"): Long data tables (All Projects, My Portfolio, Heatmap) dynamically adapt to the visible screen area: header rows remain pinned on top, horizontal scrollbars remain visible, and large or external monitors display more rows without outer window scrolling. Strategy Flow's Fit to screen leverages identical viewport math. On narrower viewports, the top navigation compresses rather than wrapping.
  • 💹 Financials Tab Layout: Financial bar chart and Changes over time table now render side by side; any finance row lacking an import period is flagged as no period with clear remediation steps for the PMO.
  • 🏢 Closed Projects in Strategy & Views: Strategic objectives itemize closed projects (year figures only) without creating false gaps in strategic coverage; Strategy Flow marks them as "closed projects only". In project views, locked milestone buttons indicate closed status, Snapshot Now is locked, and the Closed pill on All Projects toggles visibility while updating count totals accurately.
  • ✨ Typography & Layout Readability: Strategy year lines wrap cleanly, number ranges never break awkwardly after hyphens, Executive Story totals align consistently, export radar labels no longer overlap the chart canvas, and the export overview column is renamed "% used". Health & Setup displays "checking …" while checks execute.

Fixes & Stability

  • • Strategy Export Labels: Budget charts in Strategy exports are accurately labelled Approved budget and Actual to date (previously labelled "Plan this year").
  • • Finance Period Attribution: A finance row without an explicit period now attributes to the year it was last modified, rather than defaulting to the current running year (which previously rolled prior-year figures forward each January).

For Site Owners & Administrators

  • • No Setup Run Needed: When updating from 1.8.2, no list schema changes are required. Optional configuration: Settings → Currency.
  • • Finance List Maintenance: The PMO maintains the Finance list as figures arrive from finance. Health & Setup flags any rows missing a Period with actionable guidance (enter the period directly in the list; Setup cannot infer it).
  • • Full-Width Page Section Recommended: SharePoint standard sections limit web part width to ~1,200 px; placing PPM Compass 360 inside a full-width page section allows the application to utilize the full display resolution (detailed in the Site Owner guide).

v1.8.2 | Schedule Governance, Re-Baselining & Security Hardening

6 November 2026 — Production Build (SPFx 1.8.2.0)

Package Version 1.8.2.0

Adds a column to the Projects list and one to the Finance list, so a Site Owner runs Setup once after updating (see upgrade instructions). Any earlier version can update directly.

Data Kept: Setup only adds what is missing. All projects, reports, milestones, configurations and permissions stay as they are.

Security & Compliance

Fixes:
  • • Dependency with Published Advisories Updated: The PDF export library (jsPDF) lists DOMPurify as a dependency. Version 3.4.16 has three advisories, one rated critical (GHSA-cg2g-xh64-v4q7, GHSA-mrv2-3pqr-j5jr, GHSA-c6gr-qvv4-5v3f). DOMPurify was never part of the delivered package (jsPDF needs it only for HTML-to-PDF, which the app doesn't use). The dependency is now pinned to the fixed version 3.4.17, so scanners report it clean.
  • • Query Hardening: One SharePoint query used a project-type name without escaping apostrophes; it is now escaped like all other queries. This could not expose data; a name with an apostrophe could only make that query fail.
  • • Links and Images: Project links (Edit Project and Quick Links) accept only web addresses starting with https:// or http://, or a SharePoint path starting with /sites/. The project image accepts only .png, .jpg, .jpeg, .gif and .webp files; SVG images and "Copy link" sharing links are refused.
  • • Clearer Save Errors: When SharePoint refuses a save, the form shows SharePoint's readable sentence instead of the technical error text.
Status:
  • • Dependency scan of production dependencies: 0 critical, 0 high. Remaining moderate findings are in Microsoft's SharePoint Framework packages, which only Microsoft can update.
  • • Code review for cross-site scripting, unsafe HTML or DOM use, and injection through input fields (including dates): no exploitable path found. A summary report is available.
  • • Penetration test in the browser with a Site Owner account (script and link payloads in 20+ fields, export preview, deep links, baseline log): no exploitable path found. Report with evidence available. A test with Member and Visitor accounts follows.
  • • Unchanged: no Microsoft Graph or API permissions; no calls outside the SharePoint site the app is installed on.
Changes that Affect Access:
  • • Team Sites: Setup on a team site now shows a warning that the Site Owner confirms, instead of refusing. On a team site connected to a Microsoft 365 group, every group member is a Site Member and can edit project data. A dedicated communication site remains the recommendation.
  • • Change Request Approval in the App (New, Off by Default): When switched on, the app lets only the configured approvers (Sponsor; Sponsor and portfolio manager; or those plus the PPM team) approve or reject. It refuses requests that changed meanwhile and records who decided. This is an app rule: a Site Member can still change the approval status directly in the SharePoint list (visible in version history). If approvals must be tamper-proof, use a Power Automate approval flow instead.
  • • Like all business rules in the app (own projects only, locked reports, the new baseline lock), these rules guide what the screens allow. SharePoint permissions remain the security boundary (after Site Owner Tools → Security & Permissions → Apply): Visitors read only, Members edit without delete, settings and financial lists protected.

What's New in Schedule Governance & Approvals

  • 🩺 Project State and Health: Shown directly in the project header: the state (Not Started, Running, On Hold, Closed) and the overall health (worst of the four ratings).
  • ⏰ Overdue and Past Due Milestones: Past due: the date has passed since the last status report (a reminder). Overdue: a report was submitted after the date and the milestone is still open. Delayed now only means "expected later than planned". The "Milestones on time" tile counts Overdue, Delayed, At Risk and On Track.
  • ↺ Re-Baseline Milestones: After an approved change request: select milestones, shift them by a number of days or enter dates, and choose the date accuracy. Every re-baseline is recorded on the project (date, change request or reason, person, old and new dates). The PPM team can also correct a baseline, with a reason.
  • ✅ Approvals Page (Optional, See Security): Approve or reject submitted change requests in the app, designed for sites without an automated Power Automate approval flow.
  • 🧩 Choose Columns on My Projects and My Portfolio: Fully configurable columns, as on All Projects. New column additions: State, Reporting and Target end.
  • 💹 Financial Figures Over Time: The Finance list now keeps one set of figures per project and import period (the PMO adds them, for example after each budget review). Every screen shows the latest period; the Financials tab shows the period and, from the second period on, a chart and table of how the approved budget, actual to date and LE changed.

Improvements

  • • All Projects Filters: One Filters button (State, Health, Type, include archived) with a removable chip for each active filter; saved presets include them.
  • • Reporting Reminders: Not Started and Closed projects are never flagged; On Hold projects are paused by default.
  • • Milestone Forecast Retention: Completed and cancelled milestones keep their forecast; it can be changed after reopening the milestone.
  • • Next Milestone Display: Shows the earliest open milestone, also when its date has passed. Milestones of Closed projects no longer count as late.
  • • Re-Baseline Audit Badge: After a re-baseline, the forecast's "since last snapshot" badge is grey and names the re-baseline, because an agreed change is not a slip.
  • • Project Header Wrapping: Long values in the project header wrap inside their column.

Fixes

  • • Status Report Header Updates: After submitting a status report, the project header, ratings and Status History update at once, also when you switch tabs without clicking Done.
  • • User Display Resolution: "Submitted by" and "Sponsor at the time" show the person's name for accounts that have no e-mail address in SharePoint.

For Site Owners & Administrators

  • • Run Setup Once: Run Setup once after updating to apply list schema additions.
  • • Finance List: New column Period (YYYY-MM); a project can now have several rows there. After each budget review the PMO adds a new row per project with the new period instead of overwriting the old one (see the Site Owner guide). LE and Actual YTD count as "this year" only when the latest period is in the current year.
  • • New Settings: Change request approvals (off by default) and Status reports → Projects on hold (pause reminders by default).
  • • Licensing: The publisher can now issue time-limited evaluation keys (valid on any site, at most 90 days).
  • • Security & Permissions → PPM Lists in Site Contents: Show the hidden PPM lists in Site Contents again, or hide them again (search stays off). After the app is removed the lists and their data stay on the site; the Site Owner guide explains how to unhide or remove them.
  • • Terms of Use Links: The Licence tab and the Setup wizard link directly to the Terms of Use.

v1.7.4 | Cross-Project Capacity Intelligence, Locked Allocations & Adaptive Reporting

4 October 2026 — Production Build (SPFx 1.7.4.0 · Consolidates 1.7.x)

Package Version 1.7.4.0 (Consolidates 1.7.x)

No new lists or columns, and no Setup run needed when updating from 1.7.0 or later. Older versions run Setup once as before (see upgrade instructions).

Zero-Friction In-Place Updates: For updates that require no list schema modifications, Site Owners see a subtle update notice once per version rather than a setup prompt. The "run Setup" banner triggers only when a release introduces structural migrations.

What's New in Resource Intelligence & Adaptive Governance

  • ⚠️ Cross-Project Over-Booking Warnings: A compact ⚠ indicator appears directly inside the Resources rating card, project header, step 2 of status reports, and on My Portfolio whenever a team member is booked beyond capacity across all active projects over a rolling 3-month window. Updates dynamically without page reloads; projects on hold are automatically excluded.
  • 🔍 12-Month Cross-Project Booking Inspector: Click any team member's name or the ⚠ over-booking warning on the Team tab to inspect a complete 12-month cross-project allocation breakdown across every active project in the tenant, eliminating surprise resourcing collisions before work begins.
  • 🛡️ Automated Allocation Quality Checks: The Team tab actively validates resource health in real time: flagging team members booked past the project target end date, identifying upcoming milestones without allocated personnel, and highlighting extreme overallocation (>120%).
  • 🎯 Strategic Effort Tracking (FTE per Objective): Strategy view now displays planned human effort alongside financial budgets, showing planned team allocation as an average annual % FTE per objective to connect operational capacity directly to high-level strategic priorities.
  • 🔒 Finalized Baseline Allocations & Audit Locking: Submitting a monthly status report automatically finalizes and locks team allocations from two months prior (e.g. submitting the September report locks July, keeping August open for actual reconciliation). Finalized months display an audit lock badge (🔒) on the Team tab to prevent inadvertent edits.
  • 📈 Plan-vs-Actual Variance Tracking: Planned team values for future months are permanently recorded. Excel exports display both planned baseline and actual recorded effort, enabling automated variance reporting.
  • 📄 Adaptive Document Exports & True One-Pagers: Executive exports dynamically preserve clean layouts. When summary text overflows, font size scales adaptively before cleanly continuing to page 2; Goal/Scope/Success and Strategy links are intelligently included if room allows; drag-and-drop section reordering in the export dialog; and optional Strategy Flow slide in Executive Story exports.
💼 Business Impact & PMO Value

Cross-Project Resource Governance Without Expensive Add-ons: Enterprise PMOs gain portfolio-wide capacity intelligence without deploying expensive third-party resource management tools. Automated over-booking alerts prevent burn-out, 12-month inspector reveals cross-project commitments in one click, and baseline allocation locking (🔒) ensures historical capacity audits remain 100% trustworthy and tamper-proof.

For Site Owners & Administrators

  • • Zero-Touch In-Place Updates: When updating from 1.7.0+, no setup action is required. A one-time notice confirms the update without displaying unnecessary setup banners.
  • • Audited Month Reopening: The PPM team and portfolio owners can reopen a locked historical month on the Team tab ("Reopen a month…") with a mandatory justification reason, which is permanently logged in the project audit history.
  • • Streamlined People & Access Directory: User administration displays clean full names with compact action icons for role reassignments and removals, eliminating technical login strings.

Enterprise Maintenance & Updates

How updates are delivered, applied and tested in your tenant.

How do updates reach my tenant?

PPM Compass 360 is packaged as a standard Microsoft SharePoint Framework (SPFx) package (.sppkg). You upload the updated package to your tenant App Catalog and click Deploy. Zero server access or PowerShell scripting required.

How does data migration work during updates?

All your data lives securely in your own SharePoint Online lists inside your tenant. After each release, a Site Owner runs Setup once (the app shows a reminder); it adapts existing lists and items to the new version and keeps your historical status reports, milestones, risks, and audit logs.

Can I roll back to an older version?

No. Backward rollbacks are not supported. When a new release introduces structural changes to SharePoint lists (such as new columns, views, or calculations), the list schema moves forward. For this reason, we strongly suggest testing each new package on a staging/sandbox site before rolling it into production.

How do we get notified of new updates?

Customers receive proactive release notifications with download links and changelogs. You control the deployment timing in your tenant App Catalog and can validate on a sandbox site at your own pace.
