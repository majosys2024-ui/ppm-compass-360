v1.1.0 Latest Release
September 27, 2026 - Production Build (SPFx 1.1.0.0)

Package Version 1.1.0.0 (Unified Commercial Milestone)

This single entry covers all enhancements since 1.0.4.0 (incorporating internal builds 1.0.4.1 and 1.0.4.2). The cornerstone of this release is a simpler, safer native SharePoint permission model: editors are the site's Members, readers are its Visitors, managed directly through SharePoint's standard "Share site" interface.

What's New

  • 🛡️ Simple Native Permission Model: Everyone you add to the site as a Site Member can create and edit PPM data; everyone added as a Site Visitor can open the app and read. Site Owners (and the optional PPM team group) manage the app. Nobody except Site Owners can delete PPM data ("Contribute Without Delete").
  • 💡 "Can Only Read" Hints: When selecting a sponsor, project leader, deputy or portfolio owner who lacks edit rights, the form alerts: "… can only read - ask a site owner to add them as a Site Member." Assigning a project role never alters anyone's SharePoint access by itself.
  • ⚙️
    Settings Page for Site Owners (Site Owner Tools → Settings): One unified administrative hub eliminating the need to ever open raw SharePoint settings lists:
    • Modules: Toggle Resource Management (with a switch for team roles), Decision Log, usage statistics, and Project Health Radar display.
    • Governance: Configure edit restrictions, PPM team group, permission shortcuts, the "Site Visitors can see financial figures" toggle, and the audit list "People with project roles who can't edit".
    • Portfolios & Cadence: Assign portfolio owners and deputies by email address, with individual reporting cadences per portfolio.
    • Support: Direct support contact configuration and user guide links.
  • ⚡ Refresh Button & 5-Minute Intelligent Data Caching: Available on the title row of every data page (My Projects, All Projects, My Portfolio, Search, All Milestones, All Risks & Issues, Analytics, Heatmap). Keeps loaded data in memory for 5 minutes for rapid page browsing; Refresh pulls latest multi-user updates on demand with last-synced timestamps. Local changes always display immediately.
  • 🧙 4-Step Guided Setup Wizard: New sites are provisioned in 4 structured steps (Modules → Starting Values → Create Lists → Next Steps). On existing sites, the Review choice values action on Choice Lists reopens the starting values step anytime.
  • 🔔 Upgrade Reminder Banner: When an updated package is deployed, Site Owners see an automated notification banner requesting a 1-click Setup run to verify schema migrations.
  • 🔄 Copy a Rejected Change Request: A rejected CR now features a + New Change Request button that clones the request for the same project, pre-filling the title, description, and next sequential CR number for effortless re-drafting.
  • 🧭 Official Product Identity: Fully named PPM Compass 360 in the Microsoft App Catalog and SPFx web part list. New sites display this name; existing sites preserve their configured title.

Improvements

  • Choice Values Protection (Calculation & Filter Locking): To safeguard calculations, KPIs, filters, locks, and risk-cost exposure figures from breaking, critical status fields are locked against accidental renaming or deletion in SharePoint:
    Field Locked Values & Behavior
    Project Overall Status Not Started, Running, On Hold, Closed (fully locked)
    Milestone Status Not Started, On Track, At Risk, Delayed, Completed, Cancelled (fully locked)
    Milestone Event Type Gate (locked; other custom event types remain freely editable)
    Date Accuracy Exact Date, Week, Month, Quarter, Unknown (fully locked)
    Risk/Issue Type Risk, Issue (fully locked)
    Likelihood & Impact Low, Medium, High (fully locked)
    Risk Rating Low, Medium, High, Critical (fully locked)
    Risk Status Open, Resolved, Closed, Accepted (Monitoring, Mitigating, Escalated stay editable; custom values supported)
    Change Approval Status Draft, Submitted, Approved, Rejected (Deferred stays editable)

    Fixed system values shown read-only on Choice Lists: RAG values (Green, Yellow, Red, N/A) and Decision Status (Draft, Recorded). Setup warns if a locked value was renamed directly in SharePoint.

  • ✔ Instant My Projects Loading: The core project table renders immediately on navigation; summary tiles and columns fill in progressively as background queries complete, avoiding misleading temporary "0" counts.
  • ✔ Status Report Rigor & Safe Submit: Output % (0% accepted) and Team Engagement are required; low engagement (1-2) requires an explanation in the Yellow/Red reason field. Months are selected from a calendar grid blocking past-start, duplicate, or future reporting periods. Submissions update the project summary first and lock reports last, while re-submitting in the same month safely updates milestone snapshots without duplicating rows.
  • ✔ Enforced Quality Fields: Mandatory Portfolio on projects (when portfolios exist), start/end dates on active projects, actual dates on completed milestones, estimated cost on High/Critical risks, and decided-by/date/rationale when recording decisions.
  • ✔ Progressive Milestone Dates: A project's first status report prompts for baseline dates across open milestones; subsequent reports require forecast dates on all baselined milestones ("Unknown" valid).
  • ✔ Immutable Project Numbers: Project IDs cannot be changed post-creation to safeguard linked Finance and ERP spreadsheets. Site Owners retain emergency rename capabilities with automated finance guidance.
  • ✔ Safe Team Allocation Retention: Removing a team member or clearing all allocation months preserves an empty row in the background instead of deleting list rows; re-adding that person cleanly reuses the record.
  • ✔ Decision Concurrency & Natural Sorting: Eliminates duplicate decision numbers during simultaneous saves; alphanumeric natural sorting ensures D-1000 correctly sorts after D-999.
  • ✔ Entra ID & M365 Nested Group Recognition: Users belonging to the PPM team group through nested security or M365 groups are recognized with full administrative rights.
  • ✔ Accessibility & Focus Trapping (WCAG): Modals trap keyboard focus inside, auto-focus initial fields, and restore focus to triggering elements upon dismissal.
  • ✔ Human-Readable SharePoint Titles: New and modified items receive meaningful Title attributes (e.g. "PRJ-104 - Go-live") for clear readability in native SharePoint list views.
  • ✔ UI Refinements: My Portfolio standardizes on the shared portfolio bar; Health & Setup features a compact table; Security & Permissions wraps long descriptions with resizable columns; Project Health Radar switch hides visual charts while data tracking continues in the background.

Fixes

  • ✔ Dynamic Portfolio Picker on New Sites: All portfolios (e.g. Portfolio A, B, C) can be selected in the New Project modal even after owners have been configured for some of them.
  • ✔ Instant Project Type Phase Loading: Newly added project types, phases, and portfolios render immediately in project forms without requiring a browser page reload.
  • ✔ UTC Date Normalization: Decision dates are stored uniformly in UTC, eliminating 1-day date slippage for sites located east of UTC.
  • ✔ Conditional Action Rendering: When the app cannot verify write access, it cleanly hides the New/Edit Project action buttons instead of displaying unclickable controls.

Security & Permissions Architecture

  • 👥 Editors (Site Members): Can create and edit projects, milestones, risks/issues, change requests, status reports, decisions, and allocations - but cannot delete anything ("Contribute Without Delete"). Configuration lists (settings, portfolios, phases) remain read-only.
  • 👁️ Readers (Site Visitors): Can read all project registers. Visibility into financial budget/actual figures is controlled via the "Site Visitors can see financial figures" setting (enabled by default for executive stakeholders).
  • 🔒 User Preferences: Item-level security guarantees that users can save their own personal view preferences, but cannot alter or inspect other users' preferences.
  • 👑 Site Owners: Retain full administrative control and are exclusively authorized to delete records.
  • 📦 Dependency Hardening: Excel export components and all underlying packages updated to audited versions without known security advisories.

For Site Owners - Upgrade Steps

  1. Run Setup (Site Owner Tools → Health & Setup): Adds new settings, validates locked choice values, configures the PPM team recognition row, and checks site architecture (Site type and Dedicated site).
  2. Review Members & Visitors: Click ⚙ (top right) → Site permissions → Share site, then allocate users as Member (editors) or Visitor (readers). Settings → Governance provides a shortcut and lists "People with project roles who can't edit" to identify pending editors.
  3. Configure Financial Visibility: Verify Settings → Site Visitors can see financial figures based on your organizational policy.
  4. Apply Security Settings: In the Security & Permissions tab, tick all lists and click Apply to selected.
  5. Validate Access: Verify with one Site Member (can create/edit, cannot delete) and one Site Visitor (can view, cannot edit).
  6. Licensing: Copy buttons for Tenant ID and Site Collection ID are available on the License tab for immediate license activation.

For IT - Site & Architecture Requirements

  • Dedicated SharePoint Communication Site: New installations must be provisioned on a dedicated communication site (Setup refuses execution on M365 Group team sites). Communication sites provide clean, isolated Owners/Members/Visitors groups without unnecessary mailboxes, Teams channels, or group document sprawl. Existing team site installs remain supported.
  • Dedicated Site Scope: Non-PPM lists on the same site share Member permissions; Health & Setup issues an advisory if unrelated list content is detected.
  • Teams Integration: Web part runs natively on SharePoint pages, or can be pinned as a Website tab in Microsoft Teams.
  • Standard SharePoint Groups Only: Operates entirely without custom security groups or scripted directory modifications.

Enterprise Maintenance & Update Guarantees

Designed specifically to comply with enterprise IT governance and zero-risk change controls.

How do updates reach my tenant?

PPM Compass 360 is packaged as a standard Microsoft SharePoint Framework (SPFx) package (.sppkg). You upload the updated package to your tenant App Catalog and click Deploy. Zero server access or PowerShell scripting required.

How does data migration work during updates?

All your data lives securely in your own SharePoint Online lists inside your tenant. Each release automatically migrates and adapts existing list items so they work with the new version. Your historical status reports, milestones, risks, and audit logs are fully preserved.

Can I roll back to an older version?

No. Backward rollbacks are not supported. When a new release introduces structural changes to SharePoint lists (such as new columns, views, or calculations), the list schema moves forward. For this reason, we strongly suggest testing each new package on a staging/sandbox site before rolling it into production.

How do we get notified of new updates?

Customers receive proactive release notifications with download links and changelogs. You control the deployment timing in your tenant App Catalog and can validate on a sandbox site at your own pace.
